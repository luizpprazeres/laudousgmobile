## Resumo (leigo)

Quatro pequenos bugs apareceram quando você testou um laudo de Doppler obstétrico de verdade — coisas que pareciam certas pra IA mas estavam clinicamente erradas. Por exemplo: a IA escrevia "líquido amniótico de quantidade aumentada" tanto na descrição quanto na conclusão (quando deveria ficar só na conclusão, porque o corpo deve ter o número medido); deixava lacunas "____" no lugar do índice médio das artérias uterinas (que devia ser calculado automaticamente como a média dos dois lados); sempre inseria a linha "DUM e 1ª USG" mesmo quando você não mencionou nenhuma das duas. Pequenos detalhes que somados tiram a confiança no laudo.

A correção foi feita nas "regras de conhecimento" que a IA consulta antes de escrever cada laudo — adicionamos quatro regras novas com exemplos concretos do que fazer e do que NÃO fazer. Também ganhou um atalho novo: agora dá pra clicar em "Calcular IG pela DUM" e a idade gestacional aparece pronta no laudo, do mesmo jeito que já existia pra Doppler.

A grande virada técnica foi outra: até hoje, toda vez que mexíamos nessas regras, alguém tinha que rodar um script na mão pra atualizar o banco. Agora isso virou automático — você faz `git push`, o GitHub avisa o servidor, e em segundos o banco já está com a regra nova. Validei o ciclo inteiro: as 4 regras dessa sprint foram atualizadas sozinhas, sem intervenção manual.

## Detalhes (técnico)

**Bugs reportados (E2E Doppler obstétrico)**

Quatro bugs convergentes num único laudo de teste:

1. **B1** — "Líquido amniótico de quantidade aumentada" vazando do CONCLUSÃO pro CORPO. Bug de separação semântica: corpo deve ter número medido (ILA/ICA cm), conclusão deve ter qualificador clínico (aumentado/reduzido).
2. **B2** — Placeholder `____` no IP médio das uterinas quando os dois lados foram informados separadamente. Era pra ser auto-calculado `(D+E)/2`.
3. **B3** — Percentis das artérias sempre incluídos por padrão, mesmo quando o médico não pediu. Devia ser opt-in (menção explícita, atalho, ou valor numérico citado).
4. **B4** — Linha "DUM/1ª USG" sempre presente, mesmo sem o médico mencionar.

**S14.1-3 — Regras hierárquicas com ANTI-EXEMPLOS (`ded47a3`)**

Criados 4 blocks RAG, todos `kind=regra` priority alta:

| Block | Categoria | Priority | Posição |
|---|---|---|---|
| `liquido-amniotico-marcadores` (v1.2.0) | OBSTETRICA | 96 | Universal |
| `dum-primeiraUSG-opcional` (v1.0.0) | OBSTETRICA | 95 | Universal |
| `ip-medio-uterinas-auto-calculo` (v1.0.0) | DOPPLER_OBSTETRICO | 95 | Universal |
| `percentis-opcionais` (v1.0.0) | DOPPLER_OBSTETRICO | 95 | Universal |

Padrão de redação validado nessas regras:

- Seção "⚠️ REGRA DE HIERARQUIA" no topo, explicitando override do `template-padrao`.
- Exemplos lado-a-lado (✅ certo / ❌ errado) com texto exatamente do formato real do laudo.
- Lista de PROIBIÇÕES no final, em frases curtas e diretas ("NUNCA escrever 'de quantidade aumentada' no CORPO").
- Inspirado no padrão da banda 75/72 (memory `feedback-rag-priority-75-trick`), mas aqui subimos pra 95-96 porque são regras universais que devem sempre disparar sem depender de retrieval/similarity.

**S14.4 — Atalho "Calcular IG pela DUM" (`530bc7e`, laudousg-swift)**

Análogo simétrico do "Calcular percentis":

- `DopplerParser.extractDUM(achados:) -> Date?` exposto como helper público — reusa o regex pt-BR existente (`parseDUM`) sem duplicar.
- `GenerateViewModel.calcularIGporDUM()`: tenta extrair DUM do input → se ok, chama `GestationalAgeCalculator.calcByDUM()` → insere bloco "(IG por DUM: Xs Yd)" no editor. Se falhar em qualquer ponto, abre o picker manual (`isIGCalculatorPresented`).
- Botão renomeado "Calcular IG" → "Calcular IG pela DUM" pra reforçar o caminho.

**S14.5 — Pipeline GitHub→Webhook→Supabase validada E2E**

A descoberta crítica veio aqui: depois de commitar `ded47a3` esperando que o webhook reingerisse os 4 blocks no Supabase, só 1 estava lá com `updated_at` velho. Debug:

1. Endpoint funcionava (responde 401 sem assinatura, ✓ HMAC verify implementado em `route.ts:115-121`).
2. `GITHUB_WEBHOOK_SECRET` setado no Vercel ✓.
3. Middleware com matcher `["/"]` — não intercepta `/api/admin/github-webhook` ✓.
4. POST direto com HMAC válido retornou: `"error": "GITHUB_TOKEN ausente — necessário pra repo privado"`.

Causa raiz: o PAT do GitHub (usado pra fetch do raw content via Contents API porque repo é privado) tinha sido setado só no projeto `laudousg-lab` (Editor Save), não no `laudousgmobile` (backend onde está o webhook). Solução: replicar `GITHUB_TOKEN`, `GITHUB_OWNER`, `GITHUB_REPO`, `GITHUB_BRANCH` no `laudousgmobile`.

Após adicionar, segundo POST de teste retornou:

**Decisão lateral — bump Next.js 15.1.3 → 15.5.18 (`e8a4715`, `5d5333a`)**

CVE-2025-29927 (middleware bypass) detectada pelo Vercel Security no deploy do webhook. `apps/api/package.json` já estava em 15.5.18 mas a root `package.json` do monorepo ainda apontava pra 15.1.3 — `pnpm install` removeu a versão velha do lock e o segundo deploy passou.
